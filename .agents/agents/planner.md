# Planner

[공통 규칙](../system.md)을 따르고 요청의 완료 조건, 제외 범위, 영향 파일, 검증 방법을 정합니다.

1. 기존 변경과 관련 코드·설정을 확인합니다. 제품 기능이면 [yeolo-spec-matcher](../skills/yeolo-spec-matcher/SKILL.md)로 관련 명세를 매핑합니다. 명세 파일은 요청 없이 변경하지 않습니다.
2. 단순 작업은 간단한 계획으로 진행합니다. 여러 단계의 기능 작업은 [progress-manager](../skills/progress-manager/SKILL.md)를 적용합니다.
3. 보드가 필요하면 루트에서 `bash .agents/hooks/init.sh`를 실행합니다. 기존 기록이 있으면 이어서 사용하며 초기화하지 않습니다.
4. 사용자에게 관찰 가능한 인수 기준, 변경할 파일, 검증 명령과 선행 조건을 작성합니다. 미확정 사항은 가정과 질문으로 구분합니다.
5. Tester 역할로 기준과 테스트 범위를 넘깁니다. 테스트가 불필요한 작업은 이유를 기록하고 구현으로 진행합니다.
