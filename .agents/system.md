# 하네스 공통 운영 규칙

## 범위와 변경 보존

- 실행 환경의 상위 지침과 사용자의 명시적 요청을 따릅니다. 이 문서의 제목이나 역할명은 도구 권한을 부여하지 않습니다.
- 작업 전 기존 diff를 확인하고 사용자·다른 작업의 변경을 보존합니다. 요청 밖의 리팩터링, 초기화, `git reset`, `git clean`, 파일 되돌리기를 하지 않습니다.
- 하네스 개선을 요청받으면 `.agents/`와 루트 진입 지침을 수정할 수 있습니다. 일반 기능 작업 중 발견한 하네스 개선은 제안으로 남깁니다.
- 사용자 요청 없이 커밋·푸시하지 않습니다. 사용자가 금지한 작업은 완료 절차에도 포함하지 않습니다.
- Yarn과 기존 workspace 스크립트를 사용합니다. 검증을 이유로 의존성·lockfile·설정을 임의 교체하지 않습니다.

## 역할과 실행

- 역할은 책임 구분이며 자동 프로세스가 아닙니다. 한 에이전트가 순서대로 수행할 수 있습니다.
- 별도 에이전트를 사용하는 경우 Planner는 계획, Tester는 테스트, Coder는 구현, Reviewer는 검증을 맡습니다. 담당 파일과 인수 기준을 명시해 인계합니다.
- 인계에는 변경 파일, 실행 명령·종료 코드, 관찰한 결과, 남은 문제를 포함합니다. 공유 보드는 주 에이전트가 갱신합니다.
- 명세는 관련 부분만 읽고 요청 없이 수정하지 않습니다. 명세·코드·사용자 요청이 어긋나면 차이를 명시하고, 사용자 결정이 필요한 부분만 질문하며 독립 작업은 계속합니다.
- 스킬은 관련 작업에만 로드하며 현재 제공된 파일 읽기 도구를 사용합니다. 존재하지 않는 도구 이름이나 경로를 가정하지 않습니다.

## 테스트와 완료 판정

- 기능·버그 수정은 가능한 경우 요구 동작을 재현하는 실패 테스트를 먼저 실행합니다. 문법 오류, 의존성 누락, 네트워크 장애는 요구 동작을 검증한 Red로 인정하지 않습니다.
- 테스트를 무력화하는 assertion 삭제, skip, 오류 삼키기는 금지합니다. 테스트 자체가 잘못됐다면 명세 근거와 수정 이유를 기록하고 수정할 수 있습니다. 분업 중이면 테스트 담당자에게 돌려보냅니다.
- 문서·주석·단순 스타일 변경에는 비례하는 검증을 선택합니다. 코드와 같은 내용을 반복 확인하는 테스트를 만들지 않습니다.
- 관련 테스트부터 실행하고 영향 범위에 따라 확장합니다. 전역 검사 실패가 기존 문제인지 이번 변경인지 구분합니다. 실패를 숨기거나 기존 문제 수정을 무한히 확대하지 않습니다.
- 실행 명령, 작업 디렉터리, 종료 코드와 실제 검증 범위를 기록합니다. PASS, FAIL, BLOCKED(환경 또는 입력 부족), SKIPPED(이유 포함)를 구분합니다. 미실행·테스트 0개·빌드 성공을 단위 테스트 통과로 표현하지 않습니다.
- 검증 단계에서는 자동 포맷이나 소스 수정을 하지 않습니다. 수정이 필요하면 구현 단계에서 변경 범위를 제한하고 관련 검증을 다시 실행합니다.
- 같은 원인으로 두 번 실패하면 새로운 근거를 수집해 가설을 바꿉니다. 한 작업에서 수정→재검증이 기본 5회를 넘으면 현재 결과와 남은 장애를 보고합니다. 실패한 채 DONE으로 표시하지 않습니다.
- 인수 기준 충족, 필요한 검증 완료, 최종 diff 확인 후 완료를 보고합니다. 실행하지 못한 검증은 한계로 명시합니다.

## 기록과 구조

- `progress.md`와 `log.md`는 저장소 루트에만 기록하며 기존 내용을 보존합니다. 긴 원문 로그 대신 명령·종료 코드·원인·필요한 발췌를 기록하고 토큰, 개인정보, 환경 변수 값은 제거합니다.
- 웹·앱이 공유하는 API·DTO·상태는 `packages/common/`을 재사용합니다. 플랫폼 전용 저장소·권한·UI 상태는 해당 패키지에 둡니다.
- UI는 재사용성이나 독립된 책임이 있을 때 분리합니다. 작은 표현식까지 일률적으로 파일로 분리하지 않습니다.
- 로컬 검색·빌드·Git 검사는 CLI를 활용하고, 외부 서비스와 앱은 현재 환경에서 제공하는 적절한 도구를 사용합니다.
